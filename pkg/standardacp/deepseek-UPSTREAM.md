# DeepSeek Harness ACP

The npm launcher `@deepseek-ai/dsh` version `0.2.2-rc.1` runs the official ACP v1 server with `dsh --profile acp`. The server identifies itself as `deepseek-harness-acp` version `0.0.1`. It persists new sessions before returning their IDs and resumes exact IDs in their original physical working directories without replay. It exposes native model and reasoning options, list, resume, close, cancellation and standard MCP. Its usage notifications measure current context occupancy. [ACP contract](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/acp/acp/README.md#protocol-contract)

Model discovery through `session/new` creates a persistent record. A management client can isolate the probe by prepending a temporary `--patch` that points the JSONL persistence row to a temporary root and disables the session-projection cache. Keeping the selected `DSH_HOME` preserves the model provider configuration. [T3 Code probe](https://github.com/pingdotgg/t3code/blob/6ac68172675d79a7e1d68252c0359a216e128698/packages/provider-acp-registry/src/server/probe.ts)

## Invocation usage

The adapter reads the appended portion of the exact same v4 JSONL journal in `DSH_HOME/sessions` for a matched ACP prompt. Plain and concatenated Zstandard logs are supported. It checks the session header, physical workspace, file identity and baseline tail, then accepts one completed root turn with one directly admitted user message. Only valid `assistant/message` request reports contribute usage. Native input already excludes cache read and cache write. Retries, delegated sessions and other calls can fall outside the observed subtotal. Unknown counters remain unknown. Persistence writes live events in batches, so the adapter gives a pending terminal batch one bounded follow-up read. [Native persistence format](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session/session-persistence-jsonl/README.md) · [CC Switch journal reader](https://github.com/farion1231/cc-switch/blob/721ca8e08c5233f41e9a79cc367d581ac1ec4bcd/src-tauri/src/services/session_usage_dsh.rs)

## Exact native fork

The shipped ACP server omits `session/fork`. On the verified npm release, the adapter starts one scoped process based on the same ACP profile and executable. A temporary overlay replaces its ACP transport with one native fork operation over stdio. The operation uses an exact current-format observation from the selected persistence service and calls the published `buildForkSeed` and Agent creation APIs. The selected journal position binds the terminal sequence, native turn and admitted user message. The helper checks those values against the source ID and workspace, then flushes and disposes the independent child before returning its ID. The existing ACP connection resumes that ID and mounts its requested resources. The helper checks the resolved npm package version before invoking its fork API. The installation owner supplies launcher-version evidence through the management path. [Launcher overlays](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/boot/app-boot/README.md) · [Native fork API](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/session/README.md#fork-a-session) · [Native agent factory](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent/README.md)

The installed macOS release was exercised through the Go adapter with an isolated home and offline provider responses. The checks covered two hot turns, model changes, cancellation, exact-ID cold resume, fork from an older verified turn after the source had advanced, independent source and child continuation, persisted child resume and fork receipt reconciliation. Production credentials and other platforms require separate acceptance.
